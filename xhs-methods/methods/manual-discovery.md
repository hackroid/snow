# 手动发现处理方法

用户亲手刷到并交来的帖子（截图/链接/文字转述＋状态反馈），
按下列最小闭环处理；不为此新建引擎或数据库，用追加式记录。

1. 保存证据原件于私有位置。无平台 ID/链接时分配本地
   evidence_id；不编造链接、ID 或作者身份，不为补 ID 去
   搜索作者或追踪已删帖子。结构记录不写作者名/头像。
2. 追加一条记录：图上/用户明示的进 facts，拿不准的进
   uncertain（年份、精确日期、交通角色、目的地是否确定等
   分开列），两者永不混写。
3. 用户反馈（已满/已删/成团/联系结果/「不相关」）以事件
   追加引用同一 evidence_id，不静默覆盖旧记录。「不相关」
   须连同当时规格与原因记录，只对该规格成立。
4. 关闭状态只对当前证据版本成立：以后有可信重开证据时
   追加 reopen 事件并按新状态重评，旧通知不复活。
5. 后来拿到可信链接/ID 时追加 link 事件显式关联；只凭
   标题相似不得合并记录。样本雪场不在既定范围时只作方法
   样本，不自动扩围。
6. 从样本提炼的找帖思路只进 candidate（见学习方法），
   一个样本不直接改现行策略；推荐流可见不等于搜索可检到，
   结果事件不给关键词记因果功过。
