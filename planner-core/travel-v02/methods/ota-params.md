# OTA 渠道参数与口径（Agoda / Yahoo!トラベル / Booking.com）

与 orion-params.md 并列，记散订 OTA 的可复用检索步骤、核心参数与失败退路。价格口径总则见 method.md（应付额为准、未兑现回馈不扣、资格未知不冒充符合）。

## Yahoo!トラベル（travel.yahoo.co.jp）

- 积分呈现从本项目报价口径（`travel-v02/methods/method.md` §4.1，口径示例）：主价不抵扣任何积分；积分回馈/即时抵扣/既有积分支付仅作备注并区分性质与条件。
- 检索 URL 核心参数（2026-11-11 batchN 实证）：kwd=地名（如 妙高高原）、cid=入住日 YYYYMMDD、cod=退房日、ppc=成人人数、rc=房数、si=1（安い順，点击「安い順」页签后出现且生效）、discsort=1。一次列表后按现金价升序深核，列表计数为施設数。
- **积分即時割引（すぐに使う）与还元是两个口径（2026-11-11 官方说明纠正）**：Yahoo 官方 campaign 页确认「すぐに使う」＝ポイント即時割引——把**本次预约预计获得的积分即时抵扣**到本次应付额，可免注册/免登录/免报名，**不要求既有积分余额、也不要求 PayPay 关联**（旧记述"花既有积分"已撤回，属错误解释）。同一房分开记四数：(1) 未即时使用的原总额（现金应付，税込）；(2) 本次预计积分即时抵扣额；(3) 抵扣后实际应付（即时口径，也是真实应付口径之一）；(4) 不即时使用时另行获得的未来返还（还元）。**(2) 与 (4) 不可兼得**：即时抵扣已把预计积分用掉，不得再计未来返还。用**既有余额积分支付**是另一回事（官方 guide/QA 另有说明），与即時割引分开记、不混淆。通用活动的率与条件（如通用 10% 有在线信用卡支付、除外设施等条件）只是活动层口径；**具体 plan 的率与付款/资格条件以该 plan 页文案为准**——页上没核到就标条件待核：不得把通用规则冒充该 plan 已验证，也不得以"需要既有积分"为由丢弃即时价。条件支持时即时价可作附付款条件的公开报价并列，未核时作条件价并列。
- 单价构成在 plan 弹窗内訳核对（大人単価×人数＝小計），判断整间总价还是每人价以弹窗为准；列表价带条件参数（cid/ppc/rc）可直接引用。
- 入湯税/宿泊税：物件页未必载；plan 弹窗「料金について」常有"宿泊税がかかる場合…含まれません"的通式注记——金额未示即 unknown，不得当 0；明示金額（如 入湯税 ¥150/人/泊）作现地必付另列，不并入房价、但参考合计要算入并标注。
- 取消：预订按钮上的"○月○日までキャンセル料無料"与弹窗 policy 表并读；policy 表可能只有部分行（当日/不泊），缺逐日表就记部分表记，不补全。

## Booking.com（www.booking.com）

- 检索退路（batchN 实证）：直达拼参数 URL 可能被附加 chal_t 并重置条件显示 0 件——不要绕过，改用站内搜索表单（目的地联想→日历→人数→Search）即正常。核心参数：ss/dest_id、checkin/checkout、group_adults、no_rooms、selected_currency=JPY、order=price（安い順，参数可生效，页首会明示 "Sorted by: Price (lowest first)"）。
- **总价口径**：列表混有"税前标题价＋税费行"与"税费含总价"两种显示——比较价一律取税费含总价（整间・1 泊・全员）；按标题价排序会与总价排序颠倒（实证差 ¥171）。详情页回显日期/人数/房数再读价；税额内訳未示即不拆。
- Genius/会员/手机价：只见"登录后可能有 Genius 折扣"提示而无 Genius 价时，资格 unknown、按标准价比较；出现资格价与标准价并存时双记、比较用标准价。cashback/credit 类回馈不扣除。
- 现地必付费（入湯税・都市税类）：详情未载即未载，不推定为 0 也不推定有；免费取消多为同房另一价位方案，两个价都记、最廉方案的取消条件以其自身为准（常见不可退款＋预订时全额支付）。
- 到目标雪场的距离：物件页常无特定雪场距离（页内检索雪场名零命中即 unknown），"Ski-to-door"、评论里的邻场说法不作目标场依据，不估算。

## Agoda

- 口径已在 batchA/batchM 实证：用应付总价（含税费、结账口径），"after Cashback"类低价不是应付额不采用；赞助割引若已反映在应付额内则照实记。列表价与物件页房价区实价可不一致（实证 ¥20,569 vs ¥19,718），以房价区 offer 实价为准并保留差异。排序安い順本次两批均生效，但不据此声称全平台最便宜。

## 一休（www.ikyu.com）

- 积分呈现同样从本项目报价口径示例（`travel-v02/methods/method.md` §4.1）：一休与 Yahoo!トラベル 同系（Yahoo 侧 plan 由一休提供），同有「すぐに使う（ポイント即時割引）／貯める」切换——读价前切「貯める」，主价取不抵扣积分的应付额（税込、整间）；获得ポイント率/额只作备注并记性质（页无活动文案时性质 unknown，不推定常驻/等级）。
- 检索（2026-11-11 batchO 实证）：关键词框不可靠（输入地名无联想、回车清空、首搜回全国无条件结果）——用地域导航：/region/area/ → 県ページ（新潟 pr15）→ エリア页 /area/ma<编号>/（妙高 ma015007；注意一休的"妙高エリア"编入了斑尾等跨区物件，物件所在地与自有雪场须逐家核，不能按エリア名认目标）。列表参数与 Yahoo 同族：adc=1、cid/cod=入住/退房 YYYYMMDD、ppc=成人、rc=房数、discsort=0、lc=1；安い順为路径段 /si1/。首页切积分开关会清空搜索表单，先定模式再填条件。
- 物件页 URL（/000<物件ID>/）带 cid/ppc/rc 而**不带 cod**——退房靠页面"1 泊"回显，链接引用时注明打开后复核回显。价格构成在 plan 详情（"大人3名税込◯◯円"为整间总价；每人价未明示时不反推冒充明示价）。入湯税/宿泊税逐家读金额：明示单价×人数＝现地必付（长野县宿泊税官方口径：2026-06-01–2029-05-31 每人每晚 ¥200，¥6,000 门槛按**不含餐・税前**宿泊费计——以物件页明示另付金额为据计入，不用含餐整价÷人数推断门槛，页未明示不自算，batchO 实证）；只有通式注记的金额 unknown。

## 连锁酒店官网（Route Inn 实证，route-inn.co.jp）

- 检索流程（2026-11-11 batchO 实证）：官网 → ホテル一覧 → 地方页 /hotel_list/?area=<编号>（中部=4）→ エリア见出し下分店；分店页 /hotel_list/<県>/index_hotel_id_<id>/，房型/容量页在其后加 price/。预订经「空室検索・ご予約」浮层（日期只读点开日历、翻月用月名旁 ">"；Guests 弹窗逐室 +/-）→ 新标签 reserve.route-inn.co.jp（Tripla 控件）：参数 checkin/checkout=YYYY/MM/DD、type=plan、rooms=URL 编码 JSON [{"adults":N}]、code=分店 UUID。
- **先核容量、后核价格（逐店逐房核）**：逐家分店核官网房型构成与预订控件的单室人数设置。房型床数本身不证明定员，须以定员表记/控件上限/实际检索结果合并判断；检索回零须区分原因（无此人数选项/售罄/未上架/未知）并逐项记依据事实。某批查过的分店结论只是该批变量，不固化为品牌或区域结论——换店、换日期重新核。无合容量分店时价格步不启动，不改房数/人数凑结果。
- 控件 quirks：结果页初载空白约 20 秒（刷新后 URL 规范化）；默认 USD 显示，URL 参数 mcp_currency=JPY 会被覆盖回 USD，币种用页右上按钮切换——非 JPY 显示的价格不入报价（本批 2 名旁证价因此只记证据、不比价）。官网不假定比 OTA 便宜；同物件与 OTA 合组时各自保留价格/权益/读取时刻。
