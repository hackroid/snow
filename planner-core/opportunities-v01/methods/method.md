# method — 机会日历＋优惠票（不变量）

## 1. 日期推导（机会日历）
- 窗口期：每批以**实际运行日（JST）**为起点、向后 8 周（56 天）。不预设用户从下一个周末起出行，也不预设任何窗口会被采用。
- 周末：周六/周日对。公共假日（祝日/振替休日/国民の休日）与周末相邻（周五或周一相接、或连成串）时，窗口可扩展为多日窗。
- 普通窗口默认形态：1 泊 2 滑。多日窗只作**建议**呈现（可能泊数/滑雪天数照实标），**不推断**公司休假、周五年假或已确定可去；每个窗口带"需项目所有者确认"的可用性字段（实际可用日期由项目所有者给出，本模块不查私有日历）。
- 年末年始的惯例休业（12/29–31 等）**不是祝日**，单独标注为惯例期，不与祝日混同，**也不代表用户在该期间有假**。
- 开放注记三分（2026-11-11 验收固定）：每窗按 conditions 已核计划逐场归类——**已核计划尚未到**（计划开业日在窗口之后）、**计划未知**（未発表/未核）、**按已核计划预计可营业，实际待核**（计划开业日已到，但计划≠实况）。有任何一场计划未知，就不许写"均未开业"；只有计划、没有实况核对，就不许写"均已开业"。
- 窗口永远是**机会候选**，不是确认行程；被 planner 采用前必须经用户选定。
- 假日只认内阁府「国民の祝日」官方清单（官方清单当轮另采，台账未随导出包），取数存原始快照，逐日按官方名录核对（含振替休日）。

## 2. 优惠票核法（来源与资格）
- 渠道只收：雪场/运营方**官方**渠道，或页面可证的**明确授权**销售渠道。聚合/转售/个人出品不收。每场每批最多深核**两类**渠道。
- 每条必备字段：雪场、雪季（须 26–27；非当季标"历史参考"）、渠道类型（早割/网购/会员价/套票等）、产品名、适用雪场范围、可用滑雪日与**黑名单日期**、资格（成人定义/年龄/会员要求）、票天数与连续使用限制、购买与兑换方式、价格（须含税口径；另有必要费用单列）、**购买截止**、退款/转让限制、直达链接、读取时刻、在售状态（在售/未上架/售罄/历史参考分开记）。
- **资格未知 ≠ 可用**：资格（年龄/会员/居住等）未核清的条目不能用作默认最低价锚点；比较表里把官方定价基线单列，优惠条目带资格列并排显示。
- **未查到限制 ≠ 已核无此限制**：购买截止、黑名单日期、连续使用/起用条件等，页面没写不等于不存在——deadline_rule 只能填实际核到的规则（填 "none" 须有"无截止"的明确依据），blackout_dates=[] 须有"无除外日"的依据，七项 checks 的 true 须逐项有据；查不到就留 unknown/held，不得为让条目 admitted 而补 none/[]/true。（2026-11-11 batchM 杉ノ原公式票纠正：价目表只有价格与季期，截止/除外/连续条件未载明，两条官票由 research_ready 改 held。）
- **票条件补证流程（2026-11-11 batchQ 固化）**：held 的票要补证时按固定范围查——票价页本体＋同站直接链接的注意事项/约款/公告＋站内检索，并把已查页面清单留进证据；在线渠道只沿官网自己给出的链接进（不猜平台），渠道商品按渠道分开记、绝不与官网窗口价拼成一个 offer；窗口当日贩售、连续使用、排除日、购入截止、换票方式、成人定义都须明确文案才算有据（价目表本身不证明购入方式）；有界补证后仍未载的，offer 保持 held 并在 note 写明已查范围——这是"已查范围未载、仍待核"，不是永久否定，后续可待官网补页或直接向雪场确认后复核。价格/期间/规则原文按当季来源存批次变量，不进方法常量。
- **准入分两层（2026-11-11 验收固定，tools/admission.py 实现）**：
  - **资料就绪（research_ready）**：七项同时核清——有效日期范围、票权范围、天数与单位、成人/会员资格、购买期限、售卖状态、来源可信状态（官方，或授权已核）。任一项 unknown → 资料 held（标原因）。**资料就绪只是数据完整，不等于适用于任何实际行程**，不得称"可用于默认报价"。
  - **行程适用（admit）**：必须有真实 context（按 planner spec 形状：目标雪场、**全部**滑雪日期、当前购买日期、会员事实）。无 context → **held_for_trip_context**。行程层逐项相核：目标须在票权范围内、全部滑雪日在有效期内、购买时刻不晚于截止（固定截止或"首滑日前"规则）、单位/数量可实现。**会员资格必须是用户明确事实**——"入会免费"只说明门槛低，不等于用户已是会员；未确认 → held。捆绑票（枚单位）的数量/共享规则未实现前行程层一律 held，不拿均价代总支付。套餐已含票时仍为 alternative_only（替代、永不抵扣）。
- **授权标注**：销售来源的授权身份未核（如仅见卖方自称）→ 标"销售来源候选/授权未核"，不得称"已授权"；有雪场官网直链、运营方公告点名等明确依据，才可标授权销售。
- **捆绑产品均价**：多枚綴り等捆绑的"总价 ÷ 枚数"只是**购买均摊参考**，不是每人每日价；单位（枚 vs 人日）与数量不匹配不得计价，未核可否多人同日使用/分日使用/余票与退款规则前一律 held，不假设可拆卖、共享或跨日。
- **不叠加**：套餐已含票时，优惠票只是替代选项，永不从套餐价里再扣一次；**便宜不等于权益相同**——范围/天数/兑换方式/退款差异与价格并列，不以单一价格排序掩盖差异。
- 截止已近：在结果中显著标注（本模块不建提醒/订阅）。

## 3. 向 planner 交接
- 日历交接：窗口以结构化条目给出（起止日期、类型 ordinary/extended、形态 泊/滑、相邻假日名、需确认项）。用户选定窗口后，planner 才可将其用作 spec 日期（测试/实际判断仍按 planner 方法）。
- 票交接：条目以结构化字段给出（价格、天数、范围、起始日、资格、截止）。交接方式（已接通，2026-11-11 起经 entryrun3/batchM 等多批实证）：批次把 offers 作顶层 ticket_offers、把购买时刻与会员事实作 purchase_context 交 planner-v01 统一入口（combine），入口在 prepare/validate 内以本模块 admission 两层逐候选重筛——research 层在本模块完成，admit 层只认本轮 context（spec 全滑雪日、购买时刻、会员事实），结果（选用/held/alternative_only 与小计影响）由入口渲染。本模块仍只做研究与准入判定：不产小计、不写报价候选、不改 planner 口径；research_ready 只是资料齐备，永不等于已计价。
- 本模块不产小计、不产行程；planner 的已知小计口径不因本模块改变。

## 4. 变量与不变量
不变量：本方法的推导、核法、字段与交接口径。变量：每批的运行日、8 周日期、假日、价格、在售状态、剩余期限——只存批次，不写成用户永久偏好。
